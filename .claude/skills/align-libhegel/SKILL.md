# Aligning the OCaml binding to a new libhegel release

`libhegel` is a Rust cdylib built from hegel-rust's `hegel-c` crate. hegel-ocaml
calls it in-process via ctypes: `lib/ffi/ffi.ml` `Dl.dlopen`s the library at
module init and declares every symbol with `Foreign.foreign` — no subprocess,
no wire protocol. When the pinned version changes, the C API in
`hegel-c/include/hegel.h` may have added, removed, renamed, or re-typed
symbols, and the binding layer must be re-aligned. The public `Hegel` API
(`hegel.mli`: `run_hegel_test`, `Generators`, `Stateful`, the settings) must
**not** change as a result — only the internal layers.

The layers, and what an ABI change usually touches:

- **`lib/ffi/ffi.ml` + `lib/ffi/ffi.mli`** — the whole ctypes surface. Three
  things move together: the raw `c_*` `foreign` declaration (which must mirror
  the C prototype exactly), the OCaml-native wrapper below it (allocates
  out-params, `check_rc`s the return code, copies engine buffers), and the
  `val` in `ffi.mli` (abstract handle types + doc comment). Most alignments
  end here.
- **`lib/internal.ml`** — the test runner and the typed-draw wrappers on top
  of `Hegel_ffi.Ffi` (run lifecycle, `generate_*`, spans, pools,
  `with_string_generator`). Touch it when a call's shape or lifecycle changes.
- **`lib/generators_core.ml`** — the collection protocol
  (`with_collection`) and the `Labels` module (span-label constants). Touch it
  when the collection ABI or `HEGEL_LABEL_*` values change.
- **`lib/stateful.ml`** — the state-machine callers. Touch only if the
  state-machine protocol changes.
- **`lib/ffi/loader.ml`** — the pin itself plus baked-in artifact checksums;
  regenerated by scripts, not hand-aligned (see §1).

**Within the binding layer, the raw `c_*` declarations _must_ track the C
API.** When a C function gains a parameter, the `foreign` type grows with it.
A behavior-preserving default for a new _optional_ parameter (a NULL callback,
a nullable pointer, a `0`-means-default flag) is absorbed inside the OCaml
wrapper — but that absorption must be **documented in a comment on the `c_*`
declaration** so a future reader can tell a deliberate default from an
oversight. Example: the `callback`/`user_data` pair taken by `hegel_run_start`
/ `hegel_test_case_from_blob` is absorbed as NULL (engine output stays on
stderr), and the comment above `c_run_start` says so; `c_generate_float`'s
`width` is fixed to 64 in the wrapper the same way.

## The context-based ABI

Every fallible libhegel call follows one convention, and the binding is shaped
around it:

- The **first argument** is a `hegel_context_t *` (an error-reporting
  context) — `ptr void` in the binding.
- The **return value** is an `int` result code (`HEGEL_OK` is 0; failures are
  negative — `-1` is `HEGEL_E_STOP_TEST`, `-2` is `HEGEL_E_ASSUME`; the full
  list is the `e_*` constants in `ffi.ml`).
- Any **value the call produces** (a handle, a count, a bool, a buffer) is
  written through a **trailing out-parameter**, never returned.
- On a non-OK return, the human-readable message is read back from the context
  via `hegel_context_last_error`.

`check_rc ctx rc` funnels every fallible call: `HEGEL_E_STOP_TEST` →
`Stop_test` (choice budget exhausted; the runner unwinds to `mark_complete`
with OVERRUN), `HEGEL_E_ASSUME` → `Assume_rejected` (`mark_complete` with
INVALID), any other non-OK code → `Backend_error` carrying the context
diagnostic. On `HEGEL_E_STOP_TEST` a constructor leaves its out-parameter
NULL, so wrappers `check_rc` **before** reading the out-param.

### Ownership: caller-owned handles, freed exactly once

Collections, variable pools, and state machines are opaque caller-owned
handles with matching destructors (`hegel_collection_free` /
`hegel_pool_free` / `hegel_state_machine_free`); freeing twice is undefined
behaviour, NULL is a safe no-op. Who frees what in hegel-ocaml:

- collections → `Generators_core.with_collection` (`Fun.protect`, so a
  `Data_exhausted` mid-draw still frees)
- state machines → `Stateful.run`, the same way
- variable pools → the test case: `Internal.new_pool` records the handle in
  the test case's `owned_pools`, freed by `run_test_case` once the case
  completes
- string generators → `Internal.with_string_generator`: built from
  `tc.context`, used for one draw, always freed
- run / settings / test-case / result / failure handles → `Internal.run_test`
  and its `Exn.protect ~finally` blocks

Engine-allocated `{data, len}` buffer results (`hegel_generate_bytes`,
`hegel_generate_string`) are **copied immediately** into an OCaml string
(`string_from_ptr`) and then freed with their matching `*_result_free` — never
hold the raw pointer past the free. A new handle type needs the same
treatment: an abstract type in `ffi.mli`, a destructor binding, and a decided
owner with an exception-safe free.

Note: the published reference at <https://hegel.dev/reference/libhegel> has
been stale on ownership before (it documented the pre-0.31.0 `int64_t` ids
long after they became handles). The authority is `hegel-c/include/hegel.h`
at the pinned tag, and `nm` on the actual artifact.

## 1. Find the pinned version and fetch the matching header

The pin lives in `lib/ffi/loader.ml` as `let version = "..."`, alongside a
baked-in table of SHA-256 checksums for the release's `libhegel-<os>-<arch>`
artifacts. After editing the version, the checksums **must** be regenerated
with `scripts/update-checksums.py` (reads the version back out of loader.ml;
requires `gh`) — stale checksums make the loader's download fallback fail for
every user. The CI bump script (`.github/scripts/bump_hegel_rust.py`) does
both, so on a bump branch this is already done.

The release **tag is `v<VERSION>`** (note the `v` prefix — the raw path
without it 404s):

```bash
curl -sSL https://raw.githubusercontent.com/hegeldev/hegel-rust/v<VERSION>/hegel-c/include/hegel.h
```

Diff it against the previous pin's header first — if the two are identical,
the alignment is a no-op and you only need `just check` to confirm.

## 2. Get the matching library

There is no vendoring: `Hegel_ffi.Loader` resolves the library at runtime, in
order — `$HEGEL_LIBHEGEL_PATH`, a bundled dune-site copy (release tarballs
only), a sibling `../hegel-rust/target/{release,debug}/` checkout, then a
SHA-256-verified download cached under
`${XDG_CACHE_HOME:-$HOME/.cache}/hegel-ocaml/libhegel/<VERSION>/`. On CI the
download fallback just works (the bump regenerated the checksums).

**Pitfall: a sibling `../hegel-rust` checkout shadows the download** and is
almost certainly on an *older* tag than the one you just pinned, so tests
would run against a stale engine. If one exists, point the loader at the real
artifact explicitly:

```bash
VERSION=$(awk -F'"' '/let version =/{print $2}' lib/ffi/loader.ml)
curl -fsSLO "https://github.com/hegeldev/hegel-rust/releases/download/v${VERSION}/libhegel-linux-amd64.so"
export HEGEL_LIBHEGEL_PATH="$PWD/libhegel-linux-amd64.so"
```

(macOS: `libhegel-darwin-arm64.dylib`.)

**When you need the symbol table**, run `nm` against the artifact — ground
truth for which `hegel_*` symbols exist:

```bash
nm -D "$LIB" | grep ' T hegel_' | sort     # Linux .so
nm -gU "$LIB" | grep hegel_ | sort         # macOS .dylib
```

`Foreign.foreign` resolves each symbol eagerly when `ffi.ml` is initialized —
a symbol the binding declares but the lib no longer exports raises
`Dl.DL_error` naming it, so **every** test binary dies at load.

## 3. Compare hegel.h against `lib/ffi/ffi.ml`

Walk every C declaration and check it against the binding. For each function
this library uses, three places move together: the **`c_*` declaration**, the
**OCaml wrapper**, and the **`val` in `ffi.mli`**. Categorize each header
change:

- **Removed symbol** → delete its `c_*` declaration, wrapper, `ffi.mli` val,
  and callers (re-route `internal.ml` / `generators_core.ml` / `stateful.ml`).
  A leftover declaration kills everything at load (see §2).
- **Renamed/retyped symbol** → update all three together, plus any caller
  that consumed the old shape.
- **New symbol** → bind it **only if the library needs it**. `ffi` is not
  coverage-gated, so a dead binding compiles — but the repo's style is thin
  1:1 wrappers for what's used. If nothing calls it, note it in the commit
  message and move on.
- **Changed signature** (a new arg, or a value moving from return to
  out-param) → remember the convention: ctx first, `int` result-code return,
  produced value through a trailing out-param read after `check_rc`. A new
  _optional_ arg with a behavior-preserving default may be absorbed in the
  wrapper, but document the absorption in a comment on the `c_*` declaration
  (the `c_run_start` precedent).
- **Changed enum/constant values** → update the `ok`/`e_*` result codes, the
  `phase_*`/`hc_*` bitmasks, the `mode`/`backend`/`verbosity`/`status`
  variants and their `*_to_int` mappers, and `result_status`'s
  `HEGEL_RUN_STATUS_*` decoding — all near the middle of `ffi.ml`. If
  `HEGEL_LABEL_*` values move, update `Labels` in `lib/generators_core.ml`;
  binding-invented labels (`function_result = 1001`) must sit *past* the last
  upstream value so they can't collide.
- **Changed struct layout** (`hegel_date_t`, `hegel_time_t`,
  `hegel_datetime_t`, the `*_result_t` buffer structs) → update the matching
  `structure` module at the top of `ffi.ml` (`Date_struct`, `Bytes_result`,
  …). Declare fields in exact C order with exact C-width types and `seal`;
  ctypes computes alignment and padding itself — no manual padding fields.

## 4. ctypes specifics — the things that bite

- **Integer widths mirror the C prototype literally**: `int` for C `int` and
  plain C enums, `int64_t`, `uint64_t` (`Unsigned.UInt64`), `uint32_t`
  (`Unsigned.UInt32` — the phase/health-check masks, float width), `size_t`
  (`Unsigned.Size_t`), `bool`, `double`. OCaml `int` is converted at the
  wrapper (`Int64.of_int`, `Unsigned.UInt64.of_int`, …). If the header widens
  an enum-typed parameter to a fixed-width integer, retype the declaration to
  match — a signed/unsigned mismatch marshals identically for small values,
  so only a literal read of the header catches it.
- **Handles are `ptr void`** in declarations; type safety lives in
  `ffi.mli`'s abstract types (`context`, `settings`, `run`, `test_case`,
  `collection`, `pool`, `state_machine`, …). A new handle kind needs a new
  abstract type there.
- **Out-parameters**: `allocate <typ> <initial>`, pass it, read `!@out` —
  only **after** `check_rc` (on `HEGEL_E_STOP_TEST` a constructor leaves the
  out-param NULL). Nullable out-handles map NULL to `None`
  (`next_test_case`, `result_failure`).
- **Engine-returned strings**: a `char **` out-param is borrowed and
  NUL-terminated — copy it immediately with
  `coerce (ptr char) string_opt !@out` (NULL → `None`). Length-delimited
  buffers come back as `{data, len}` structs — `string_from_ptr … ~length:n`,
  then call the matching `*_result_free` (they may contain interior NULs and
  are not NUL-terminated).
- **`const char *` arguments**: use the `string` / `string_opt` typs (ctypes
  copies; NUL-terminated, so interior NULs would truncate). Length-delimited
  byte arguments (`const char *` + `size_t`, e.g. `include_characters`) go
  through `optional_bytes_arg` instead.
- **String arrays (`const char *const *`) need explicit GC roots**:
  `to_string_array` builds the pointer table and returns a `Root` that pins
  the name buffers — `CArray.of_list` alone stores raw pointers whose backing
  buffers the GC may free mid-call (the classic flaky-test bug). Always
  `Root.release` after the call returns, *before* `check_rc` can raise.
- **`None` vs `Some []` is an ABI distinction**: `optional_string_array` maps
  `None` → NULL ("no restriction") and `Some []` → a non-NULL pointer with
  length 0 (an explicit empty set). libhegel treats them differently; keep
  the three-way split.
- **Blocking calls**: only `hegel_next_test_case` uses `foreign_blocking`
  (`~release_runtime_lock:true`) — it runs all engine work between test cases
  on the calling thread. Give a new long-running, non-reentrant call the same
  treatment; everything else uses plain `foreign`.
- **When the marshalling is unclear from the header, prove it empirically**:
  a throwaway `dune utop`-style script that dlopens the real artifact and
  round-trips one value beats an afternoon of debugging a garbage struct
  field. Delete it afterwards.
- **References for unclear semantics**: the implementation is `hegel-c/src/`
  in hegel-rust _at the release tag_ (ownership, error codes, sentinel values
  like `HEGEL_STATE_MACHINE_DONE`), and hegel-go's `internal/libhegel/` is a
  second, complete binding of the same ABI to sanity-check your reading
  against.

## 5. Coverage, docs, and tests

- `lib/ffi` is deliberately **not** bisect_ppx-instrumented (see
  `lib/ffi/dune`): its mechanical marshalling stays out of the 100%-coverage
  gate. Do not instrument it and do not add `[@coverage off]` anywhere.
- Everything the alignment touches **outside** `lib/ffi` (`internal.ml`,
  `generators_*.ml`, `stateful.ml`, `lib/jane/`) is 100%-line-coverage-gated
  — new branches need tests in `test/` (see the `coverage` skill). Tests run
  against the **real** engine (the loader downloads it); there is no mock.
- `ffi.mli` and any changed public `.mli` need `(** … *)` doc comments on
  every val; odoc warnings are fatal (`just check-docs`). Reference
  non-public modules as code spans (`[Internal.note]`), never `{!…}` links.
- Run `just format` (ocamlformat) before checking; `just check-format` is
  part of the gate.

## 6. Verify

```bash
just check    # check-format + check-docs + check-tests (100% coverage)
```

This is the done-condition — the same three legs CI runs. Remember §2: if a
sibling `../hegel-rust` checkout exists, set `HEGEL_LIBHEGEL_PATH` to the
freshly downloaded artifact first, or the tests run against a stale engine.

## 7. Validation gate — independent completeness audit

The steps above are done by the same context that made the edits, so they
share its blind spots: a symbol you never noticed in the header is a symbol
you also won't notice is misbound. Close that gap with a **fresh-context
audit** as the final gate. Launch a separate agent (Task tool,
`subagent_type: "general-purpose"`) that has _not_ seen your edits and whose
only job is to check the binding against the header.

Give the agent a self-contained prompt — it starts with no context:

```
Audit the libhegel ctypes FFI binding for correctness against the C header.
Do NOT edit anything — this is a read-only verification.

1. Read the pinned version from lib/ffi/loader.ml (`let version`).
2. Fetch the matching header:
   curl -sSL https://raw.githubusercontent.com/hegeldev/hegel-rust/v<VERSION>/hegel-c/include/hegel.h
   (note the `v` prefix on the tag).
3. Extract every `hegel_*` function declared in the header.
4. Cross-check each against lib/ffi/ffi.ml. A function this library uses must
   have (a) a `c_*` Foreign.foreign declaration whose ctypes signature matches
   the C prototype literally — including integer widths and signedness —
   (b) an OCaml wrapper function, and (c) a documented val in lib/ffi/ffi.mli.
   A header function with NO binding is fine only if nothing in lib/ needs it
   (this binding deliberately binds only what it uses). Flag any declared
   symbol that is NOT in the header (raises Dl.DL_error at load, killing
   every test).
5. For every parameter an OCaml wrapper absorbs (hardcodes rather than
   exposes in its signature), check a comment on the c_* declaration explains
   the absorption. An undocumented absorbed parameter is a BURIED-DEFAULT —
   flag it.
6. Check the structure modules (Bytes_result, String_result, Date_struct,
   Time_struct, Datetime_struct) field order and widths against the C
   structs, and the ok/e_* result codes, phase_*/hc_* bitmasks, *_to_int
   enum mappers, and Labels (lib/generators_core.ml) against the header's
   constants.

Report a table of every header function with OK / MISSING / SIGNATURE-MISMATCH
/ BURIED-DEFAULT / UNBOUND-UNUSED, and a final verdict line. List
discrepancies explicitly; do not fix them.
```

The agent's report is the gate: if it comes back clean, the alignment is
complete. If it flags a `MISSING` or `SIGNATURE-MISMATCH`, return to §3–§5,
fix it, and re-run this gate. This is a genuine independent check only because
the agent rederives the header→binding mapping from scratch — do not paste
your own diff or conclusions into its prompt.
